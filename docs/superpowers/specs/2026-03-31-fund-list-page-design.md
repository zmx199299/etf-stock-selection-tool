# FundList 第二页设计文档

## 1. 背景

- 首页 `Dashboard.vue` 与全局布局 `MainLayout.vue` 已完成 UI 确认，当前阶段进入第二页 `FundList.vue` 的 UI 重构。
- 用户已提供第二页 HTML 参考稿，并明确要求先完成 Mock 状态下的页面确认，再决定是否推进更深的数据联动。
- 第二页的职责不是展示首页那种瀑布流卡片，而是承担“全量浏览、快速定位、横向比较”的主列表页面角色。

## 2. 目标

- 将 `FundList.vue` 从旧版业务表格样式重构为“首页风格外壳 + 宽表格主视图”的新界面。
- 保留高密度浏览能力，支持一次性滚动查看大量基金。
- 在第二页右上角放置“红多 / 绿多”切换，并将其定义为全局配色设置入口。
- 保持 Mock 优先，不在本轮 UI 确认阶段改动后端接口结构。

## 3. 已确认决策

### 3.1 主体布局

- 第二页主体采用宽表格主视图，对应视觉讨论中的 `A` 方案。
- 页面结构延续首页的极简设计语言，但不使用首页卡片瀑布流。
- 页面默认展示全量基金列表，用户通过顶部搜索进行快速定位。

### 3.2 顶部区域

- 顶部使用轻量头部，而非首页那种更厚重的统计卡片头。
- 左侧展示：
  - 页面标题 `全量场内基金`
  - 一行说明文案，例如总监测数量说明
- 右侧展示：
  - `红多 / 绿多` 全局配色切换器
  - 搜索输入框

### 3.3 列表浏览方式

- 列表采用整页长表滚动。
- 不在本轮加入分页。
- 表头保持吸顶，便于长列表浏览。

### 3.4 行级交互

- 每行右侧保留 `详情分析` 按钮。
- 行本身只承担 hover 高亮，不承担跳转行为。
- 进入技术分析页的唯一显式入口是 `详情分析` 按钮。

### 3.5 配色语义

- `红多`：看多 / 上涨 / 偏强信号使用红色；看空 / 下跌 / 偏弱信号使用绿色。
- `绿多`：看多 / 上涨 / 偏强信号使用绿色；看空 / 下跌 / 偏弱信号使用红色。
- 该切换不是页面私有状态，而是全局设置，后续在其他页面出现同类切换时必须共享同一份状态。

## 4. 页面结构设计

### 4.1 外层骨架

- 延续现有 `MainLayout.vue` 侧边栏与内容区结构。
- `FundList.vue` 主内容区分为两部分：
  - 顶部控制栏
  - 表格容器

### 4.2 顶部控制栏

- 风格与首页统一：白底、轻边框、圆角、轻阴影。
- 布局为左标题说明、右侧操作区。
- 桌面端左右分布，移动端自动折叠为上下结构。

### 4.3 表格容器

- 表格外层使用白色卡片容器，具备：
  - 大圆角
  - 细边框
  - 轻阴影
  - `overflow-x: auto`，保证小屏可横向滚动
- 表格维持横向信息对齐能力，不在移动端切换成卡片列表。

### 4.4 表格列

按用户确认的参考稿保留以下主列：

1. `代码/名称`
2. `昨收`
3. `开盘`
4. `现价`
5. `最高`
6. `最低`
7. `波动`
8. `涨跌幅`
9. `MACD`
10. `RSI`
11. `BOLL`
12. `MA5`
13. `MA20`
14. `多空`
15. `操作`

## 5. 视觉层级设计

### 5.1 信息层级

- `代码/名称` 左对齐。
- 名称使用深色粗体。
- 代码使用更小号的灰色等宽字体。
- `现价` 采用较高字重，但不抢过 `涨跌幅`。

### 5.2 强调信息

整张表只让以下 3 个元素成为主视觉焦点：

1. `涨跌幅`
2. `多空` 分值圆点
3. `详情分析` 按钮

这样可以在信息密度较高的情况下保持阅读节奏，不让整行颜色失控。

### 5.3 方向性色彩使用规则

- `涨跌幅` 使用最强方向性色彩。
- `最高 / 最低` 保留方向色，但强度低于 `涨跌幅`。
- 技术指标列不做胶囊标签，改为更克制的小号粗体文字。
- `多空` 使用圆点分值，作为该行的摘要信号。
- `详情分析` 使用蓝色实心按钮，作为唯一 CTA。

### 5.4 表格节奏

- 行 hover 使用轻微背景变灰。
- 不使用斑马纹。
- 行高保持紧凑，但不能牺牲可读性。
- 表头吸顶，支持长列表连续浏览。

## 6. 全局配色状态设计

### 6.1 状态归属

- 使用现有 Pinia 体系承载全局配色状态。
- 配色模式建议使用枚举值：
  - `cn`
  - `intl`
- 页面不再持有本地 `invertColors` 之类的私有临时状态。

### 6.2 持久化

- 配色模式需要做本地持久化，保证应用重启后仍能恢复用户选择。
- 持久化层可使用浏览器环境可用的本地存储方案。

### 6.3 页面接入策略

- `FundList.vue` 作为本轮第一个显式入口，必须直接接入全局状态。
- 已完成 UI 确认的 `Dashboard.vue` 需要在本轮同步接入同一状态，避免“设置是全局的，但首页不响应”的行为不一致。
- 其余页面在各自 UI 确认后继续接入同一份全局状态，不再重复定义方向性色彩逻辑。

### 6.4 颜色使用方式

- 页面不直接写死“上涨就是红 / 绿色”的判断。
- 所有方向性展示都应通过统一的语义映射获取样式：
  - 看多 / 上涨 / 强势
  - 看空 / 下跌 / 弱势
  - 中性

## 7. 数据映射与交互边界

### 7.1 数据来源

- 本轮继续沿用现有 `get_fund_list` 数据结构。
- 开发环境继续保留 Mock fallback。
- 不在本轮改造 Rust / Python 接口定义。

### 7.2 前端计算

- `现价` 使用当前数据中的 `close`。
- `涨跌幅` 由 `close` 与 `prevClose` 在前端计算。
- 其余数值字段按现有返回结构直接映射。

### 7.3 搜索

- 搜索仅支持 `代码 / 名称` 的前端即时过滤。
- 不在本轮加入复杂筛选、排序和高级查询。

### 7.4 空状态与容错

- 搜索无结果时，页面显示简单空状态提示。
- 后端不可用时继续回退到 Mock 数据。

## 8. 响应式策略

- 桌面端保持完整宽表结构。
- 小屏设备不改成卡片流，而是通过：
  - 顶部控制栏折行为上下布局
  - 表格外层启用横向滚动
来保证页面可用。

## 9. 本轮实现范围

本轮只做以下内容：

1. `FundList.vue` 的宽表格 UI 重构
2. 全局配色状态与本地持久化
3. `FundList.vue` 与 `Dashboard.vue` 对全局配色状态的接入

本轮不做以下内容：

1. 分页
2. 排序
3. 多条件筛选
4. 表头说明弹层
5. 后端接口字段改造
6. 其他未确认页面的 UI 深改

## 10. 预计改动文件

- 修改：`src/views/FundList.vue`

## 11. 验证策略

- 严格遵循 TDD：先写失败测试，再做最小实现，再回归验证。
- 若当前前端缺少测试基建，则在实现计划中补入最小测试基础设施，用于覆盖：
  - 全局配色状态读写
  - 方向性色彩映射
  - 基金行关键衍生数据计算
- 最终前端验证命令使用：

```bash
npm run build
```

- 页面行为使用开发预览配合 Mock 数据人工确认。

## 12. 设计结论

第二页的定位已经明确：它不是首页的翻版，而是“高密度、可横向比较、快速定位”的全量基金主列表。视觉语言继续跟首页统一，但主体结构回归宽表格，这是当前信息量与使用场景下最合适的方案。
