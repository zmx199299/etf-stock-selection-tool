# 第三页技术分析图表周期切换设计文档

## 1. 背景

- 第三页 `Analysis.vue` 首版 Mock 页面已经具备基础摘要、策略建议、图表区、技术指标区四段结构。
- 当前图表区虽然已有高保真 Mock，但仍存在两个明显不足：
  - 用户看不到价格刻度，无法判断图表价格区间。
  - 用户无法判断当前图表对应的是日 K、分时还是其它周期。
- 用户已明确要求第三页图表区进一步增强可读性，并支持周期切换。

## 2. 本轮目标

在保持第三页“清爽研究报告风”与第二页统一页面壳层的前提下，增强图表区，使其具备：

- 明确的周期选择入口。
- 明确的价格轴与时间轴信息。
- `分时` 与 `K 线` 两种不同的主图形态。
- 图旁解读与指标结论随当前周期同步切换。
- 所有涨跌/多空颜色继续服从全局红绿配色设置。

## 3. 已确认决策

### 3.1 周期范围

第三页图表周期固定提供以下选项：

- `分时`
- `日K`
- `5分`
- `60分`
- `120分`
- `周K`
- `月K`
- `季K`
- `年K`

### 3.2 周期入口样式

- 不采用一排按钮。
- 不放到页面顶部横栏。
- 图表区顶部右侧使用 **单个下拉框** 作为周期选择入口。

### 3.3 周期联动范围

当用户切换周期时，以下内容必须同步变化：

- 主图（分时线 / K 线）
- 左侧价格轴
- 底部时间轴
- 图旁解读文案
- 下方 4 张技术指标结论卡

### 3.4 分时图表现

- 当周期为 `分时` 时，主图不再使用蜡烛/K 线。
- `分时` 单独显示为 **分时线图 + 均价线**。
- 其它周期继续使用 K 线形态。

### 3.5 配色方案

- K 线涨跌色必须与全局设置联动：
  - `cn` 模式：红涨绿跌
  - `intl` 模式：绿涨红跌
- 分时主线、均价线、成交量柱、多空指标卡颜色也必须遵循同一套全局配色语义。
- 第三页的颜色模式切换入口继续沿用第二页同样的全局切换逻辑，而不是第三页自维护一套局部状态。

## 4. 页面结构补充设计

### 4.1 图表卡头部

图表卡顶部继续位于 `图表研判` 区块内部，但结构调整为左右两部分：

- 左侧：
  - 区块标题 `图表研判`
  - 一条当前周期摘要文案，例如：
    - `当前周期：日K，观察短线整理平台是否延续上破。`
    - `当前周期：分时，观察盘中均价附近的承接强弱。`
- 右侧：
  - 周期下拉框

### 4.2 图表主区域布局

图表区整体仍保持“左主图 + 右图旁解读”的两栏结构：

- 左侧：主图区域
  - 价格轴
  - 主图画布
  - 成交量区
  - 时间轴
- 右侧：图旁解读卡

其中左侧主图必须看起来更像真实行情软件中的图表，而不是纯色块占位。

### 4.3 分时图结构

当周期为 `分时`：

- 主图区域展示一条连续分时线。
- 同时叠加一条均价线，颜色与主线区分。
- 下方保留成交量柱。
- 时间轴显示盘中时间点，例如：
  - `09:30`
  - `10:30`
  - `11:30`
  - `14:00`
  - `15:00`

### 4.4 K 线图结构

当周期为 `日K / 5分 / 60分 / 120分 / 周K / 月K / 季K / 年K`：

- 主图区域展示 K 线实体与上下影线。
- 下方保留成交量柱。
- 左侧展示价格刻度。
- 底部时间轴根据周期变化：
  - `5分 / 60分 / 120分`：显示具体时间段
  - `日K`：显示日期
  - `周K / 月K / 季K / 年K`：显示对应周/月/季度/年份标签

### 4.5 价格轴

- 左侧价格轴至少展示 `4` 到 `5` 个价格刻度。
- 价格刻度应与当前主图数据范围一致，不能是固定无意义文案。
- 价格轴的作用是让用户一眼确认：
  - 当前价格大概在哪个区间
  - 图形的波动幅度大概如何

### 4.6 图旁解读

- 右侧图旁解读保留，但文案要按周期区分，不再固定一条文案。
- 解读重点示例：
  - `分时`：盘中承接、均价得失、量价配合
  - `日K`：短线趋势、突破/回踩、近几日节奏
  - `周K / 月K`：中期结构、平台、均线压制与支撑

## 5. 指标区联动设计

### 5.1 指标卡数量

指标区仍保留 4 张结论卡：

- `MACD`
- `RSI`
- `BOLL`
- `均线 / 趋势`

### 5.2 联动原则

- 指标区内容按当前周期切换。
- 指标值与结论文案不再固定复用同一组数据。
- 多空语义颜色同步遵循全局红绿配置。

### 5.3 视觉要求

- 指标区继续维持“总结依据”的角色，不抢主视线。
- 颜色只用于表达多空与中性，不能让页面整体变得花哨。

## 6. 数据结构边界

本轮仍为 Mock，但数据结构需要从“单组图表描述”升级为“按周期组织”，以便后续接真实数据时不推倒重来。

建议结构：

- 基础摘要区：一份共用数据
- 策略建议区：一份共用数据
- 图表与指标区：按周期分组数据

即每只基金应具备：

- `periods.intraday`
- `periods.day`
- `periods.m5`
- `periods.m60`
- `periods.m120`
- `periods.week`
- `periods.month`
- `periods.quarter`
- `periods.year`

每个周期分组至少包含：

- 周期标签
- 当前周期摘要文案
- 价格轴刻度数组
- 时间轴标签数组
- 主图所需 Mock 数据
- 成交量数组
- 图旁解读文案
- 4 张指标卡数据

## 7. 实现边界

本轮继续遵守以下限制：

- 不接真实图表库。
- 不接真实行情后端。
- 不扩展 Rust / Python 接口。
- 不在用户未确认图表区版式前推进真实图表或复杂交互。

## 8. 验证重点

本轮新增验收重点：

- 用户能一眼看出当前周期。
- `分时` 与 `K 线` 是否清晰区分。
- 价格轴与时间轴是否让图看起来更接近真实分析界面。
- 切换周期后，图表、解读、指标是否同步联动。
- 切换 `红多 / 绿多` 后，K 线和多空指标颜色是否一起变化。

## 9. 下一步

- 基于本设计文档编写图表周期切换的实现计划。
- 首版实现仍使用 Mock 数据，但把数据结构升级为按周期组织。
- 用户确认图表区 Mock 结构后，再评估是否进入真实行情和真实图表渲染阶段。
