# 第三页入口卡片与图表 Hover 设计

## 背景

当前第三页 `Analysis.vue` 已完成主体 Mock，包括摘要、策略、图表与指标区四段结构，整体样式已经得到正向反馈，不应再大幅改动主体版式。

但仍存在两个明确缺口：

1. 直接点击第三页时，当前展示的是固定示例基金，这不符合“第三页是动态分析页面”的定位。
2. 图表区域目前仍以静态展示为主，鼠标移入后无法看到当前 K 线或分时点的具体数据。

本轮设计只解决这两个问题，并保持 Mock 优先，不接真实图表库与真实后端数据。

## 目标

1. 第三页直接点击时，不再展示两个固定示例基金，而是承接第一页基金卡片数据作为默认可切换入口。
2. 顶部基金入口区只展示卡片，不重复显示摘要、策略或其它说明块。
3. 顶部卡片密度、信息层级与体量尽量贴近第一页 `Dashboard.vue` 的卡片风格。
4. 当带入基金数量较多时，卡片允许自动换行，不为了保持单行而压缩卡片尺寸。
5. 图表区增加鼠标 hover 提示能力：
   - K 线：显示日期、开盘、收盘、最高、最低
   - 分时：显示时间、价格、均价

## 非目标

1. 不改第三页主体四段结构顺序。
2. 不引入 ECharts、TradingView 或其它真实图表库。
3. 不接真实后端分析数据。
4. 不在本轮补充更多复杂 hover 字段，例如成交量、振幅、涨跌额等，除非后续单独确认。

## 设计方案

### 1. 顶部入口区

第三页顶部横栏下方增加一组“基金卡片入口”，用于承接第一页数据。

设计约束：

- 入口区只保留基金卡片，不增加说明文字块、摘要块或额外候选面板。
- 卡片视觉密度尽量与第一页一致，保持大卡片体量、圆角、信息分层和点击切换感。
- 默认最多展示 10 条基金。
- 布局采用自动换行网格，而不是固定单行滚动，也不是强行压缩卡片宽度。
- 当用户点击某张卡片时，第三页主体区域切换到对应基金的分析内容。
- 如果路由中明确带有 `code`，则直接进入该基金的详情页，不再展示顶部卡片区。
- 如果直接点击第三页且路由未带 `code`，则顶部显示卡片集合，但下方分析主体保持空态，直到用户手动点击某张卡片。

### 2. 数据来源优先级

第三页默认基金入口的数据来源按以下优先级处理：

1. 第三页顶部卡片集合默认与第一页 `Dashboard.vue` 使用同一份前端共享基金卡片数据源，默认展示其前 10 条，因此即使用户是通过左侧导航直接点击第三页，也能看到与第一页同源的基金集合。
2. 如果用户是从第一页点击某张卡片进入第三页，则第三页直接以该 `code` 对应基金进入纯详情页，不再保留同批默认卡片集合。
3. 如果路由显式带有 `code`，则第三页直接切换为纯详情页，当前分析主体以该 `code` 对应基金为准。
4. 顶部卡片集合只在无 `code` 的入口页使用；若路由带入的 `code` 不在默认前 10 条集合中，也不再为了详情页展示而额外渲染卡片区。
5. 不再使用“两个固定示例基金按钮”作为直接点击第三页时的默认入口。
6. 如果路由未带 `code` 且用户尚未点击顶部卡片，则第三页主体保持空态提示，不自动选中顶部第一张卡片。

说明：

本轮仍是 Mock 阶段，因此“第一页基金集合”先来自首页与第三页共用的前端共享加载入口，而不是第三页单独维护的一套示例基金入口数据。

### 3. 图表 Hover 交互

图表 hover 采用“跟随浮层”方案，而不是固定角落信息框。

原因：

- 更符合券商软件和行情终端的使用习惯。
- 用户能直接把光标位置与当前数据建立对应关系。
- 与当前第三页“图表作为视觉焦点”的结构更匹配。

#### K 线 hover

覆盖范围：

- 日K
- 5分
- 60分
- 120分
- 周K
- 月K
- 季K
- 年K

浮层字段：

- 日期/时间标签
- 开盘
- 收盘
- 最高
- 最低

交互要求：

- 鼠标移入某根 K 线实体或其对应交互区域时，显示浮层。
- 浮层内容跟随当前命中的 K 线更新。
- 鼠标移出图表区域后浮层隐藏。
- 浮层位置尽量避免遮挡当前命中元素；若靠近右边界或上边界，则自动调整显示方向。

#### 分时 hover

覆盖范围：

- 分时图主线区域

浮层字段：

- 时间
- 价格
- 均价

交互要求：

- 鼠标移到分时线对应点位附近时，显示浮层。
- 浮层内容随当前命中的分时点更新。
- 鼠标移出图表区域后隐藏。

### 4. 测试策略

本轮继续遵循 TDD。

至少覆盖以下行为：

1. 直接进入第三页时，顶部显示承接自第一页的基金卡片集合，而不是固定示例按钮。
2. 顶部卡片在数量较多时采用自动换行布局，不会压缩成不可读尺寸。
3. 路由未带 `code` 时，顶部有卡片但下方主体保持空态，不默认展示第一张卡片的分析内容。
4. 点击顶部某张基金卡片后，下方分析主体切换到对应基金。
5. K 线 hover 时显示浮层，并包含日期、开、收、高、低字段。
6. 分时 hover 时显示浮层，并包含时间、价格、均价字段。
7. 鼠标移出后浮层隐藏。

## 影响文件范围

预计会涉及：

- `src/views/Analysis.vue`
- `src/views/__tests__/Analysis.spec.ts`
- 与第一页卡片数据相关的共享 Mock 文件或新抽取的前端共享数据文件
- 必要时补充与 hover 交互相关的轻量工具函数文件

## 验收标准

当以下条件全部满足时，本轮设计视为验收通过：

1. 第三页直接点击后，顶部默认入口显示为承接第一页的基金卡片集合，最多 10 条。
2. 顶部入口区只显示卡片，无额外摘要或说明块。
3. 卡片密度和体量与第一页风格基本一致。
4. 卡片数量增加时自动换行，不发生明显挤压。
5. 路由未带 `code` 且未点击卡片前，下方分析主体保持空态提示。
6. 点击卡片后，下方分析主体继续保持当前第三页样式并切换到对应基金。
7. K 线 hover 浮层可显示日期、开盘、收盘、最高、最低。
8. 分时 hover 浮层可显示时间、价格、均价。
9. 相关测试与构建验证通过。
