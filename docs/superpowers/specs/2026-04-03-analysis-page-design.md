# 第三页技术分析页面设计文档

## 1. 背景

- 第一页 `Dashboard.vue` 与第二页 `FundList.vue` 已完成当前阶段的 UI 收口。
- 第二页已经被用户明确指定为后续页面的视觉基线：左侧导航栏固定不改，顶部横栏风格与宽度统一，中间内容展示区才是页面功能重点。
- 第三页 `Analysis.vue` 当前仍是简单占位页，需要先完成 Mock 结构确认，再决定是否接真实图表与真实分析数据。

## 2. 页面职责

第三页不是基金列表页，也不是单纯图表页，而是一个面向单只基金的综合分析页，承担三类职责：

- 展示单只基金的核心基础信息与当前状态。
- 用报告式结构给出可阅读的策略建议与风险提示。
- 提供图表研判与技术指标结论，帮助用户理解建议依据。

## 3. 已确认决策

### 3.1 整体风格

- 风格确定为 **清爽研究报告风**。
- 页面结构采用预览方案 **A. 研究报告主线型**。
- 保持第二页一致的页面壳层：统一顶部横栏宽度、白底卡片、圆角、细边框、轻阴影。

### 3.2 页面主顺序

页面中间内容展示区按以下顺序组织：

1. 基金基础信息摘要
2. 操作建议与策略
3. K 线 / 趋势图表
4. 技术指标结论

### 3.3 首屏结构

- 首屏由两部分组成：
  - 基础信息摘要区
  - 操作建议与策略区
- 两者占比确定为：
  - 摘要区 `40%`
  - 策略区 `60%`

### 3.4 策略建议区信息主次

- 主展示内容：
  - 操作结论
  - 买卖区间
- 次展示内容：
  - 仓位建议
  - 止盈止损
  - 持有周期
  - 风险提示

### 3.5 页面入口状态

- 从第一页或第二页点击进入第三页时，如果已带基金代码，则直接展示对应基金分析内容。
- 如果没有基金代码，则第三页允许用户在页内搜索或选择基金后再进入分析状态。

### 3.6 图表首版范围

- 首版图表区只做 **高保真 Mock 图**。
- 本轮不接真实图表库，不接 ECharts。
- 本轮目标是确认图表区的位置、大小、层次和与其他信息块的关系。

## 4. 页面结构设计

### 4.1 固定三段框架

- 左侧导航栏：沿用现有全局布局，不改。
- 顶部横栏：沿用第二页统一风格与宽度，作为页面标题与入口控制区。
- 中间内容展示区：承载第三页所有分析内容，是本轮设计重点。

### 4.2 顶部横栏

- 延续第二页的横栏容器结构。
- 左侧展示：
  - 页面标题，例如 `技术分析`
  - 当前基金名称 / 代码的辅助说明（有基金时显示）或引导文案（无基金时显示）
- 右侧展示：
  - 基金搜索 / 选择入口
  - 必要的辅助操作入口（如返回列表或切换样本，首版可先保留单一搜索入口）

### 4.3 基础信息摘要区

- 放在正文最前面。
- 采用 4 格左右的信息摘要卡布局，信息密度高但风格克制。
- 首版建议包含：
  - 基金名称 / 代码 / 市场
  - 当前价格
  - 当日涨跌幅
  - IOPV / 溢价 / 风险等级中的关键信息

### 4.4 策略建议区

- 作为首屏主视觉区域，面积大于摘要区。
- 中心位置展示一条明确的主结论，例如：观望、分批低吸、逢高减仓等。
- 周围配套展示：
  - 买入区间
  - 卖出 / 减仓区间
  - 仓位建议
  - 止盈止损
  - 持有周期
  - 风险提示
- 视觉上以一张大主卡加若干辅助小卡的方式组织，避免每个字段同权。

### 4.5 图表研判区

- 位于策略建议区之后。
- 作为页面第二视觉重点，占据较大纵向空间。
- 首版使用高保真 Mock 图，至少包含：
  - 主价格趋势图 / K 线图占位
  - 成交量辅助区占位
  - 一段图旁解读文本或重点观察点
- 该区要看起来“像可分析的真实图表”，但暂不引入真实图表库。

### 4.6 技术指标结论区

- 放在页面末段，承担“总结依据”的作用，而不是抢主视线。
- 建议以 4 个并列结论卡起步：
  - MACD
  - RSI
  - BOLL
  - 均线 / 趋势
- 每张卡只展示结论、方向和一句解释，不做复杂指标原理说明。

## 5. 内容状态

### 5.1 带基金代码进入

- 页面直接渲染完整分析内容。
- 顶部横栏展示当前基金的名称与代码。

### 5.2 无基金代码进入

- 页面不直接显示空白占位页。
- 顶部横栏保留搜索 / 选择入口。
- 中间内容区展示一张引导卡，提示用户先选择基金以查看分析内容。

## 6. 实现边界

本轮只做 Mock 设计确认，不做以下内容：

- 不接真实图表库。
- 不接真实策略引擎输出。
- 不扩展后端接口。
- 不在未确认版式前提前推进深度交互。

## 7. 验证重点

本轮验收重点不是数据正确性，而是页面结构与阅读顺序是否正确：

- 是否符合第二页统一页面壳层。
- 是否符合“摘要 → 策略 → 图表 → 指标”的阅读顺序。
- 首屏 `40 / 60` 的摘要与策略占比是否符合用户预期。
- 图表区是否足够突出但不压过策略建议。
- 技术指标区是否足够克制，不抢页面主焦点。

## 8. 下一步

- 基于本设计文档编写第三页实现计划。
- 首版实现时只做 Mock 页面与组件结构确认。
- 用户确认 Mock 后，再决定是否进入真实图表与真实分析数据接入阶段。
