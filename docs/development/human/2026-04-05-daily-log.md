## 分钟线数据获取与存储实现

**背景**：前端已定义 9 种周期（分时、日K、5分、60分、120分、周K、月K、季K、年K），但后端仅有日线数据。需要新增分钟线（1分、5分、60分、120分）的获取、存储、同步和前端查询能力。

**设计方案**（详见 `docs/superpowers/specs/2026-04-05-minute-quote-data-design.md`）：
- 新建 `minute_quote` 表，与 `daily_quote` 分离，主键 `(code, datetime, period)`
- 1分、5分、60分直接从 akshare 获取，120分从60分聚合
- 初始注入预估：1分×5天、5分×20天、60分×60天、120分×60天，合计约 442 万条 / 42 MB
- 全量数据预估：约 705 万条 / 67 MB，数据库总量约 244 MB

**东方财富 API 不可用问题**：
- akshare 的分钟线 API（`fund_etf_hist_min_em` / `fund_lof_hist_min_em`）依赖东方财富数据源
- 当前东方财富 API 返回 `RemoteDisconnected`（连接被远程端关闭），可能是限流或临时封锁
- 新浪数据源可用，但不支持分钟线
- **解决方案**：改为"按需实时获取"策略——当用户在前端点击分钟线周期（分时、5分、60分、120分）时，后端实时从 akshare 拉取该基金的分钟线数据并返回，同时写入数据库缓存。避免全量预同步的 API 压力。
- 周/月/季/年线仍从日线聚合，不受此影响。
