# Project Skills & Workflow Rules (开发纪律与项目技能)

作为本项目开发环境中的 AI Assistant，你**必须**在每次接受任务和完成任务时严格遵守以下规则（Skills）。

## 1. 跨栈修改与冷备份协议 (Cold Backup Protocol)

当用户要求进行涉及“前后端数据结构联动”、“重构”或“高风险修改”时：
- **第一步**：在修改前，使用 `tar -czf backups/backup_name_date.tar.gz [目标目录]` 对目标目录进行本地冷备份。
- **第二步**：修改后端代码，并保证通过所有单元测试 (TDD 循环: Red -> Green -> Refactor)。
- **第三步**：如果出现严重且难以解决的错误，直接提取 `backups` 中的压缩包进行回滚，保证 Git 工作区的干净度。

## 2. 持续日志与进度管理机制 (Continuous Logging System)

- **功能级更新**：在每一次完成一个具体功能点或模块（即便用户没有特意提醒），你都应当**主动且简要地**去更新 `docs/development/human/` 对应的开发日志（或在最新日期的日志中追加条目），确保项目的透明度和接力开发的连贯性。
- **每日收尾判定 (22:00+ Rule)**：
  - 每当你的对话发生在 **北京时间晚 22:00 之后**（你可以通过环境时间或与用户的进度对话推断），你需要主动向用户进行提示：
  - **提示话术**：“当前时间已较晚，是否需要我为您生成【今日项目开发代办清单】与【明日开发计划】总结，并记录到开发日志中？”
  - 如果用户同意或要求，则执行当天的收尾日志写入操作。

## 3. UI 原型确认约束 (Frontend UI Hold Rule)

- 在没有获得用户对前端页面（尤其是表格样式、布局细节、按钮去留）的明确认可前，不要擅自推进与该页面深度绑定的复杂可视化（如 ECharts）或真实网络数据请求开发。
- 当接收到新的 UI 开发需求时，首要准则：先展示骨架/原型 -> 等待确认 -> 填充复杂逻辑。
